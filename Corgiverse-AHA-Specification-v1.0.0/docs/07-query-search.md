# Query Lens and search
## Query Lens contract
Natural language compiles to the allowlisted LensPlan schema, never SQL/Cypher/code. Supported predicates are entity kind, reviewed tier, text contains, occurrence interval overlap, cited source, dependency on record and excluded source. Combine all/any within one bounded plan; one-hop/two-hop traversal with relationship type allowlist. Limits: query 2,000 characters, 20 filters, 2 hops, 500 visible nodes and 1,500 edges. Server caps apply even if the model asks for more.

Pipeline: interpret query → show editable chips and ambiguities → validate plan → deterministic retrieval/traversal → optional semantic matches → provenance expansion → explain each highlight → render temporary overlay. If ambiguity changes scope (e.g. “before the incident” with multiple incidents), ask for a target in the UI; do not silently choose. “Who did it?” yields a boundary message and offers contradictions or open questions, not an attribution plan. Model unavailable: keyword/structured filters still work, clearly labeled.

Result types: EVIDENTIARY references an existing accepted edge with its own support; CONTEXTUAL shows spatial/time adjacency with method and assumptions; SIMILARITY groups shared text/attributes with citations but no allegation or evidentiary edge. Source matches can highlight nodes without drawing any pairwise lines. Similarity overlays use a group halo and labeled connectors, not the solid edge grammar. Explain “Both statements mention eggs; shared routine only, no evidence of contact or involvement.” Even exact identifiers require provenance and review; equality itself is not guilt or an entity merge.

Why panel returns concise verifiable rationale, match category, record/source IDs, method, applied filters and uncertainty. It must not reveal or depend on hidden model chain-of-thought. No invented explanatory sentence. Clear lens restores prior layout, selection and filters; persistent domain records and case revision are unchanged. Saving a lens persists a view definition only, with separate view revision; opening it reruns against current case and shows stale dependencies.

Counterfactual exclusions traverse the reverse dependency graph, mark unavailable support, and recompute rule-based support visibility. They do not infer which hypotheses are true. A “survives” label means “still has listed non-excluded premises,” with the complete dependency list.

## Search and indexing
SQLite FTS5 indexes immutable text chunks plus current labels/annotations in separate tables. Chunk by paragraph/page boundaries, target 800 tokens, overlap ≤100 tokens, keep page/offset maps and derivative hash. Do not merge citations across pages invisibly. Escape and bind FTS queries; never pass raw model syntax. Unicode normalization is for matching only; original and derivative text remain unchanged. Diacritics and aliases are explicit options. Search results show why matched and index coverage.

Optional local embeddings are a rebuildable cache, keyed by case ID, derivative hash, chunk locator, embedding model digest and dimension. v1 uses a case-local index file with exact cosine search for ≤100k chunks; evaluate an embedded ANN extension only if measured budgets require it. Do not require a vector server. Combine lexical and semantic lists with reciprocal-rank fusion (k=60) and deterministic ID tie-breaks, label retrieval relevance as search relevance only; no evidentiary score. Disable embeddings without disabling FTS.

Index worker publishes a complete generation through atomic pointer swap; queries pin generation. Index_revision is visible and an incomplete index warns “Some new material is not searchable yet.” Rebuild from derivatives without changing case meaning; isolate indexes per case. A no-match result says “No matches in indexed material under these filters,” never “There is no evidence.” Search snippets from original redacted exports must obey export redaction policy, including hidden metadata and OCR text.
