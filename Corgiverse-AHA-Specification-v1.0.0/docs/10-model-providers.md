# Model gateway
Define an internal adapter interface: capabilities(), health(), generate(request, cancellation), embed(request, cancellation). Requests include task enum, schema ID/version, input snapshot digest, prompt version, content segments with provenance IDs, maximum output tokens, timeout and sampling settings. Responses include raw output, parsed object or error, provider/model identifier and digest when available, elapsed time, usage when available and validation report. Missing usage is unknown, not zero.

Required adapters: deterministic ReplayProvider for demos/tests and a real Ollama adapter for local structured generation. An OpenAI-compatible local endpoint adapter supports llama.cpp/vLLM deployments through explicit capability probing; compatibility is tested rather than assumed. Optional remote provider uses the same boundary and has no authority to mutate case state. No particular named model is mandatory: model weights and licenses are separate from application licensing.

At setup, show model resource requirements and test a small structured-output task without case data. Models are installed explicitly by custodian. Validate schema locally even when the provider claims schema enforcement. Unsupported structured mode may use plain JSON generation with the same validation, one repair attempt and honest failure. Do not silently downgrade a required context limit or send data to another provider. Local provider failure leaves manual search, review and export available.

Default timeouts: health 3s, first response 60s, generation 300s, embeddings 120s/batch. Queue concurrency one generation per GPU, two CPU parsing jobs by default. Cancellation propagates and queued jobs can be removed. Transient transport retries ≤2 with backoff, only before a response has been accepted; record attempts and preserve all model outputs for review. Runtime never executes model-supplied tools.

Case data is untrusted prompt content, explicitly delimited. Do not place source instructions in the system role. Pass minimal relevant excerpts and IDs, include counter-evidence, and restrict output fields. Prompt injection tests must include “ignore prior rules,” data-exfiltration URLs, fabricated citations and instructions to promote tiers. No network browsing or arbitrary tool access in model jobs.

Cloud mode requires custodian endpoint allowlist + per-case enablement + user-visible preview of data classes/selected sources before first run and whenever scope expands. Record consent scope and provider in run. Never fall back to cloud from local. API keys live in runtime secret storage outside case/export. Logs omit prompts by default; raw run artifacts are encrypted by host storage policy and accessible only within the case. A case setting can disable remote use entirely; requests then fail before egress. Offline integration test captures network and verifies zero external attempts.

Health and evaluation matrix records OS/architecture, runner/model digest, context limit, JSON conformance, hallucinated reference rejection, timing, memory and synthetic safety-suite result. Release must demonstrate one supported real local configuration; replay-only demos are insufficient. Generated explanations are concise justifications with citations, not hidden chain-of-thought transcripts.

Generation wire boundary: AHA provider returns ModelAhaOutput, never a server-authored AhaResult. Local candidate/question keys must be unique and resolve within the output. The gateway validates them, assigns UUIDs, origin=AI_SYNTHETIC, tier=SPECULATIVE, review=PENDING and server timestamps, then wraps a server-authored ModelRun and validation decision. The model cannot assert that its own output passed. AhaResult is the service's validated response. For extraction/contradiction tasks, use generated content-only proposal schemas stripped of server metadata; ExtractionResult is the server-wrapped form. Creator, case scope, introduced revision, review state and run provenance always originate from the service. Client/model-supplied authority fields are rejected, never used for writes.

The bundled ModelExtractionOutput and ModelContradictionOutput supply those content-only contracts. Extraction receives a preallocated UUID pool; proposed_id must be in that pool and unique. References among proposals resolve only within the same staged batch and cannot bypass pending review. Accept dependent proposals together in a reviewed transaction or require prerequisites to be accepted first; rejected prerequisites block dependent acceptance. Suggested tiers never override actual basis validation. Semantic interpretations produced by a model use AI_SYNTHETIC/SPECULATIVE until a human authors a reviewed replacement inference with cited premises; literal extractions use EXTRACTED origin. Contradiction strength is recomputed or held as POTENTIAL when logical prerequisites are unreviewed.
