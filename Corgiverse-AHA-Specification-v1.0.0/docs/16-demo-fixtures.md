# Synthetic demo: The Lantern Annex
All names, places, documents and events are fictional. The demo concerns a missing archive crate and an unexplained overnight incident at a fictional records annex; it does not recreate a real crime or identify a culprit. Incident severity is incidental to the reasoning mechanics. A non-graphic synthetic case is sufficient to exercise cold-case workflows without importing real allegations.

Seed sources: an attendant interview reports a red van leaving before 22:10 and an egg breakfast routine; a camera log records a red vehicle at device time 22:26; a maintenance note describes an unverified clock offset; a café receipt includes eggs without identifying the customer; a later calibration note rules out a +47 minute offset; a search log states the limited areas checked. Distinct person/vehicle IDs must not be merged merely by shared color or breakfast words.

Golden insights: breakfast lens reveals a source-backed similarity with no relationship allegation; vehicle timing conflict remains POTENTIAL until vehicle identity and clock basis are reviewed; “camera is 47 minutes fast” is retired and cannot reappear; camera calibration and vehicle identity are useful discriminating questions. Source absence in the search log is scoped to inspected areas, not proof the crate never existed.

The package includes a minimal text seed with real SHA-256 hashes, typed records, a retirement tombstone, a validated lens plan and an AHA example. This seed is contract-test data, not the full release showcase. During M2/M7 expand it into 25 synthetic documents (6 scanned PDF pages, 3 DOCX, 2 XLSX/CSV sets, labeled diagram/photos, contradictory transcripts), 60 entities, 120 observations, 40 events, 80 edges, 8 contradictions, 6 hypotheses including 2 retired, and 3 scenario runs. All generated imagery must say SYNTHETIC and contain no real person's likeness.

Separate oracle file stores expected match IDs, tier distinctions, duplicate/retirement blocks and what remains unknown; never include an “actual culprit” answer that would turn the demo into a guilt-ranking benchmark. Replayed model outputs carry provider=REPLAY visibly. Include real local generation in release evaluation separately.

Test families: valid seed; invalid extra probability field; unsupported source reference; missing edge support; synthetic promotion; impossible interval; invalid lifecycle; prompt injection; retirement paraphrase; ambiguous timezone; inconsistent anchors; cross-case citation; parser timeout; canceled job; corrupt backup. Some require app behavior tests beyond the supplied schema validator. `fixtures/adversarial.json` defines concrete test inputs and expected decisions.
