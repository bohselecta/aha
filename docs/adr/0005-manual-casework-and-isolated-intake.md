# Manual casework, isolated extraction and recovery

Date: 2026-09-16. Status: implemented development iteration; full v1 acceptance remains open.

The supplied schema/API package remains byte-for-byte unchanged. Implemented original command types now cover human events, interpretations, relationships, hypotheses, before constraints, clock corrections, conflict review, question outcomes and hypothesis successors. Accepted versions remain immutable; proposals remain pending until a person decides. Exact cited versions are loaded alongside current records in exploration. None of this enables AI generation or changes the v1 scope.

Additive application endpoints provide session resumption, case-local full-text source search and index rebuilding, paginated historical dependencies, import progress/retry/cancel, and backup health/restore rehearsal. These are implementation extensions, not claims of complete original API conformance. They use the existing cookie, CSRF, revision and idempotency boundaries. A local CLI rotates the pairing file; browser credentials and case drafts are not written to localStorage.

Receipt and extraction are separate durable commits. The original/custody receipt is committed before a persisted INGEST job runs. A successful extraction creates immutable text and locator-map derivatives and advances the case revision again. Failure, cancellation or unsupported format retains the original. One parser job runs at a time; queued/interrupted jobs are discovered on startup. Job status updates do not change accepted case meaning. The interface reconciles the case revision before showing completed extraction.

Native macOS uses sandbox-exec. Native Linux requires Landlock ABI 3 plus libseccomp and fails closed if unavailable. The tested Docker Desktop kernel has no Landlock, so Compose uses a dedicated parser service with network_mode:none, no case volume, non-root UID, read-only root, no capabilities, resource limits and additional syscall denial. A serialized file-transfer volume carries only an input copy and bounded result. The parser receives no database path, pairing secret or case credentials. This is an isolation design with passing synthetic checks, not a completed native-parser escape or disk-exhaustion audit. Native Windows extraction is disabled.

SQLite FTS indexes normalized copies of extracted text; exact quoted passages always come from hash-verified derivatives. Reprocessing selects the newest text for search without deleting older derivatives or their citations. Rebuilding the derived index does not advance the accepted case revision. Page/row/sheet/OCR coordinates are preserved in locator maps; the review interface currently issues exact text-range citations, not full graphical page-region citations.

Portable backup and restore share bounds and use stored ZIP members, avoiding self-generated compression-ratio failures. Copies and hashing are streamed. Unsupported database versions are inspected before any case writes. Integrity failures persist through rollback and restart until explicit successful verification. A recovery rehearsal calls the actual restore validator in a separate temporary directory and records the backup hash/revision. Temporary export copies expire after 24 hours; an independent recovery drill remains required.

Unfinished release work includes full proposal editing/batch review, standalone question creation, readable history beyond the latest 50 versions, saved views, graphical citation editing, complete time/identity/dependency solving, core Atlas 3D and scale targets, real local AHA generation/evaluation, briefings/redaction, migration/disk-full/worker fault matrices, LAN/offline acceptance, human usability/accessibility, and signed distribution. Optional Scene View and CASEMAIL stay disabled.
