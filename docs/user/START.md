# Getting started with Aha!

Pair the browser using the connection code and your name. This label is attributed to decisions, but it is not verified legal identity. The built-in demonstration is explicitly synthetic; none of its people or events are real.

1. Choose the synthetic case or create a new case. Title, timezone and synthetic status are explicit.
2. In Inbox, select a file and enter a receipt note. Originals are preserved by hash. TXT, CSV, DOCX, XLSX, text PDF and supported images/scanned PDFs receive extracted text where processing succeeds. Import progress shows queued, running, cancelled and completed work; retry is available. Originals are retained even when extraction fails. UNSCANNED means no antivirus scanner is configured.
3. If a subject is missing, propose a person/place/object, then accept its representation in Review queue. Shared names never merge entities automatically.
4. Open a source, select a passage in the text area, choose an accepted subject, and write what the source reports. Explain the representation. The resulting statement is pending and does not yet change accepted evidence.
5. In Review queue, inspect the cited excerpt and open the original source if needed. Enter a decision reason and accept or reject. “Accepted” confirms the representation, not its truth. New statements start with unknown time and unknown source independence. Use Propose correction to record a reviewed time range; preserve uncertain or open bounds.
6. Inspect records and their citations in Case register. Investigator notes follow the same proposal/review boundary. Use Record your reasoning to add an event, interpretation, independently justified relationship, explanation, clock correction or before/after constraint. An explanation can record what would strengthen, weaken or retire it. Every correction remains a new reviewed version. Automatic time-constraint solving is not yet available.
7. In Integrity & backup, verify byte hashes and the audit chain. A mismatch quarantines the case across restarts and blocks changes and backup. Restore trustworthy bytes, then explicitly verify again before resuming writes. A full portable backup is sensitive and unredacted. Rehearse recovery checks that the prepared backup actually restores into a separate temporary folder. Keep a separate encrypted copy and also test recovery on another device.

All actions have visible buttons and standard form controls. Tab moves through controls; Escape closes record detail and restores focus. Light/dark theme is saved locally. At narrow widths the navigation scrolls horizontally and tables retain labeled scroll regions.

If another reviewer changes the case, stale writes return a conflict. Refresh to inspect the current state before submitting a new decision. Failed requests retain editable input. Do not blindly resubmit a changed decision. Recovery through the current command-line restore flow is documented in the operator guide.

## Explore your case

Open **Case Atlas** to move between the connection map, record table, timeline, questions, saved possibilities, and source library. Search for a name or detail and use **Evidence basis** to narrow the results. Search matches all the words you enter in labels, statements, and cited passages. For passages that have not been reviewed yet, open **Search sources**. It searches extracted text, shows coverage, and returns exact quoted locations. Rebuild the index if older sources are not covered. Neither search interprets natural-language questions or reads files whose extraction failed.

Select a record to inspect its sources. **Why shown?** explains a search match. Source citations, named subjects, and reviewed relationships have separate line styles. Sharing a word never creates a relationship. **Clear lens** restores the full view without moving the map or changing the case.

In **Questions & conflicts**, compare accounts, read their limits, and follow the source material to check. Retired explanations retain their counter-evidence. In **Possibilities**, assumptions are separated from source-backed steps. Saved sample possibilities are examples; this version does not generate new scenarios.

Use Tab and Enter to select map records, or switch to **Table**. Escape closes details and returns focus to the selected control. Map and table scrolling stay inside their panels on smaller screens. The map initially shows up to 80 records, prioritizing matches; Show more increases that limit to 500. The table provides pages of 100 records so later matches remain reachable. Large-case performance acceptance is still outstanding.

## Day-to-day review

**Overview** shows received sources, extracted-text coverage, pending reviews, open questions and recent decisions. Processing coverage describes what Aha! has read; it does not measure completeness of the investigation.

**Questions & comparisons** lets you compare two accounts or explanations side by side. Existing scenario questions can be marked in progress, answered with reviewed evidence, or closed. Standalone question creation and human-set priority are still pending; investigator notes can capture checks meanwhile.

Open a record's **Version history** to inspect a cited version and see before/after values and review reasons for recent changes. A cited old version remains attached to the reasoning that used it. Retiring an explanation keeps its record; a successor needs newly introduced reviewed evidence and a reason explaining its relevance.

Reloading resumes a valid browser session. If the session has expired, pair again with a fresh connection code. Use **Sign out** when leaving a shared workstation. Draft forms are not persisted across reloads; accepted work is stored locally.
